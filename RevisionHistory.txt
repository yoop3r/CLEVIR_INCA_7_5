CLEVIR_INCA_7_5 - Revision History
===================================

Version 7.5.5.0
----------------
Driver alerts (eyes stay on the road)
- LiDAR loss-of-communication alerts restored. While LiDAR capture runs,
  a LiDAR that sends no packets for 15 s is announced by voice ("Lost
  communication with LiDAR FRONT"), shown as an error toast that stays
  up until the device recovers, and logged with capture diagnostics.
  The voice repeats every 30 s; recovery is announced ("LiDAR FRONT
  communication restored"). Devices silent from the start of capture or
  across an MF4 rollover are now caught - the previous alert could never
  fire because the packet timestamp was cleared at every rollover.
  Critical packet loss (20% or more) is still announced. "Ignore All
  Alerts" silences the LiDAR voice only; toasts and log entries continue.
- All spoken driver alerts now use one shared voice. Messages queue with
  a 3 s pause after each, so alerts never talk over each other (e.g. with
  both LiDARs down, FRONT is announced, then REAR), and a repeating alert
  cannot build up a backlog.
- Lost device (PROCESSOR / CAMERA COMMUNICATION ALERT) reworked:
  * Detection runs on the UI thread from INCA's raw device status with a
    25 s debounce; a fault stays raised across MF4 rollovers until the
    device recovers or the driver answers the alert.
  * One non-blocking alert window, with a voice and toast when
    communication is restored.
  * A single failed INCA device-list read no longer ends the drive
    (3 consecutive failures required); configuration problems are shown
    once instead of every 5 s.
  * Re-Initialize NOW runs on the UI thread and performs a full INCA
    restart (closes INCA and the Target Server, hardware settle, restart,
    signal registration). Fixed doubled device-raster counts after
    re-registration from cache.
  * Timers that used TimeSpan.Seconds (wraps at 60) now use TotalSeconds.
- INCA Target Server message alert: when the Target Server shows a message
  (e.g. lost communication with a camera) INCA is blocked until OK is
  pressed. CLEVIR now brings that message to the front, shows a toast
  that stays up and speaks "INCA Target Server message. Press OK." every
  30 s until it is answered, then confirms when it closes.
- Invalid video (lost camera) reworked. INCA localizes camera frames and
  aligns them with the MF4 data, so video lost during a recording cannot
  come back in that recording:
  * The video GO/NOGO stays RED for the lost camera until a new
    recording or Re-Initialize, instead of flickering back to green.
  * The alert and toasts name the camera and give the quick fix first:
    "Stop Record, reconnect the REAR camera, then Start Record", with
    Re-Initialize NOW as the fallback. A Target Server camera disconnect
    is quoted in the alert.
  * New "Continue Without {camera} Video" option: keeps recording vehicle
    data without that camera and silences its video alerts until its
    video is seen again in a later recording ("REAR video is back").
  * "In Valid Video Alert" voice follows the same rules as the alert
    window (silent while a Target Server message is up or after Continue
    Without).
  * Fixed a stale RED/voice alert at Start Record: frozen-data tracking
    was never reset for the last row of each grid (e.g. the REAR camera,
    LRR), so a previous freeze carried into the next recording.
- Background monitoring loop survives a failed pass instead of stopping
  for the rest of the drive. Persistent failures gray the GO/NOGO
  indicators and are announced ("Monitoring Fault Alert" / "Monitoring
  Restored").

Recording, annotations and LiDAR
- Session mileage now starts from the real odometer reading (ANNO
  RecordedMileage previously included the whole odometer).
- ANNO header rows are matched by field name instead of fixed line
  numbers, so Email/Group rows no longer overwrite Start Date/Time,
  Vehicle and Thumbnail.
- LiDAR annotation columns are named by mounting position
  (LiDAR[FRONT]_Frame, LiDAR[REAR]_Frame) for audio-to-text; logs, toasts
  and markers identify LiDARs as e.g. "LiDAR1:FRONT".
- LiDAR event markers carry the frame and UTC time of the button press,
  so ANNO frames match the pcap markers.
- Fixed corrupted pcap files: capture and marker writes to the same file
  are now serialized.
- Hesai HTTP metadata queries retry objects that time out, so capture
  manifests are complete when a LiDAR web server stalls.
- Fixed the CLEVIR record buffer being one column short, which stopped
  the background loop when CLEVIR Record mode was enabled.

Signal lists and displays
- Grid moves/resizes and cell edits are saved again on EXIT (the save ran
  after the display forms were cleared and skipped every grid).
- Accepting "use this newly saved variable file" now updates config.xml.
- Signal list CSV fields are quoted correctly (RFC 4180), so saved lists
  with quotes or commas reload; resizing a grid now prompts to save.
- DeviceRasterSignalList.txt removed; acquisition rates are read from
  INCA. Changing the device in Grid Cell Properties no longer starts a
  full INCA variable browse (which could hang INCA for 10+ minutes).
- Grid Cell Properties no longer stays stuck on "Performing Variable
  Browsing Operation..." (or the wait cursor) when a device change
  fails; grid-cell browses are logged with timing for diagnostics.
- XLSX signal lists removed; CSV is the only signal list format.
- GO/NOGO labels repaint when their displayed color differs from the
  requested one (Video Status could stay gray at record start).
- OnVehicleScreen is fixed at its designed size (controls overlapped when
  resized); distance-to-object text stays inside its label at 125%+
  display scaling; EXIT returns after Start/Stop Measurement.
- Top Down View opened from OnVehicleScreen > Displays appears on screen.
- Deprecated CoPilot, Pedestrian, LMFR Global A, LMFR HC and Target
  status screens and the Oscilloscope display.

Exit and housekeeping
- Exit dialog Cancel leaves CLEVIR fully running (teardown now happens
  after the choice); forced exits terminate instead of restarting
  initialization.
- Compression is limited to the current session's folder (Stop Record
  could rescan every past session on the UI thread).
- GM_ResidentClient.log is capped at 5 MB with one backup; concurrent log
  writes no longer truncate lines; HesaiWrapper messages go to the GMRC
  log.

Internal
- GmResidentClient split from one file into 15 partial classes; long
  methods decomposed (none over 300 lines); configuration, signal list,
  file maintenance and alert logic moved into unit-tested classes.
  249 unit tests (previously none).

Known issues
- A saved grid size is applied only as a minimum on reload, and column
  widths are recalculated from content (they are not saved in the signal
  list). Shrinking a grid or dragging a column width is therefore lost
  after restart; enlarging a grid is kept. Planned for a later release.

Version 7.5.4.0
----------------
- INCA COMM / lost-device checks now apply only after measurement or
  recording has started. Previously the PROCESSOR COMMUNICATION ALERT
  could fire while idle (before Start Measure/Start Record) when a
  processor failed to initialize. Lost-device flagging in the background
  health monitor (toast and "D" indicator paths) and CheckForLostDevice
  are gated on measure/record state.
- Data-frozen tracking (per-cell frozen counters/flags, stale-data and
  lost-device flags, frozen/lost device name lists) is reset when
  measurement starts and again when recording starts, so detection
  counts from the moment that state begins.
- INCA COMM Status always reflects the true link state: it returns to
  GREEN as soon as monitored signals resume updating and stays RED
  otherwise, including after "Ignore All Alerts for This Drive" (which
  now only suppresses the operator alert dialog).
- Fixed the PROCESSOR COMMUNICATION ALERT repeating the same device name
  (e.g. ACP3_MCU,ACP3_MCU,...); lost-device names are de-duplicated and
  cleared after the alert is handled.
- config.xml consolidation (one vehicle per config.xml):
  * Replaced <Vehicles>/<Vehicle>, <SelectedVehicleNumber> and
    <CurrentVehicleUsage> with a single root <Vehicle> holding
    <VehicleNumber> and <Processors>. Legacy files are still read.
  * Removed <CameraPositions> and <MaxCameras>; cameras come only from
    <CameraConfiguration>/<Cameras>, used in row order (row order =
    timecode signal order).
  * Folded <ZipMF4Files> into the Compression/Compress* flags; removed
    the unused ZipMyFilesNew routine.
  * InitForm shows the vehicle number read-only; Change Vehicle Number
    and Create New Experiment are administrator-only.
- Fixed an ArgumentOutOfRangeException in GridCellPropConfig when adding
  signals (DataGridView indexer arguments were swapped).
- Removed obsolete INCA 7.2/7.3/7.4 version checks; window title now
  reports INCA 7.5.
- Added an acknowledgment-only VehicleSpy Communication Failure dialog
  using CustomDialogForm when starting or resetting its measurement fails
  during an INCA recording, including measurement-start timeouts. The dialog
  replaces the temporary toast and appears after capture startup completes,
  so acknowledgment does not delay LiDAR/OXTS initialization. It explains that
  VehicleSpy data may be missing while INCA recording continues. The warning
  and acknowledgment are logged; no Exit or disable-recorder action is offered.
  Windows speech synthesis also announces "Lost communication with VehicleSpy"
  without blocking recording; speech failures are logged separately.
- Made config.xml authoritative for INCA database, workspace, experiment,
  selected vehicle, and generic Variant_Controller processor identities.
  Removed variant aliases and hardcoded identity allowlists; all configured
  processors use exact case-insensitive device matching and monitoring.
- Added explicit DataDictionary and VehicleSpySetup resource selections,
  plus INCAExperimentTemplate for NEW FULL registration. Runtime saves and
  vehicle edits preserve fleet selections and unknown XML metadata.
- Added persistent startup recovery with Edit Configuration, Retry, and
  Exit while keeping InitForm hidden. Saved edits reload and revalidate;
  cancelled edits return to the original failure. LoginForm reuses INCA
  preflight and blocks login with saved-but-unvalidated changes. Changes
  to initialized session identity/resources still require restart.
- Validation: project build, 79 deterministic configuration checks, and
  11 recovery/error-propagation checks passed. End-to-end INCA/editor
  recovery testing remains pending. See forward.md for the checklist.
- Updated the installer bundle to detect installed .NET 10 desktop
  runtimes and include the 10.0.12 x64 redistributable. MSI runtime assets
  are harvested from application output, including runtime metadata and
  the runtimes subdirectory.
- Removed retired import/vehicle-configuration editor sources and INCA
  communication backups. Added diagnostic logging to LiDAR/CANalyzer
  error paths and structured exception handling to signal comparison.
- Button14_Click (Start/Stop Record) has a Finally block that calls Me.Refresh() after re-enabling buttons and resetting the cursor, forcing an immediate repaint of the form.
  Fix: Added Me.Refresh() to Button6_Click's Finally block in OnVehicleScreen.vb, matching the existing pattern used by Button14_Click.
- Merged AudioTotextConfig.xml into config.xml under a new AudioToTextConfiguration section (PythonPath, ScriptName,
  WorkingDirectory, IntakeDir, ConfigPath, ConfigSheetName, RunValue),
  eliminating redundant configuration files.
- Updated AudioToTextProgressForm to read audio-to-text parameters from
  config.xml first, falling back to the legacy standalone
  AudioTotextConfig.xml for backward compatibility with older installs.
- Removed the standalone AudioTotextConfig.xml component from the WiX
  installer (Product.wxs) since its settings now ship as part of
  config.xml.
- Expanded the Configuration Editor to describe and validate the new
  AudioToTextConfiguration parameters, plus several previously
  undocumented/unvalidated config.xml settings: OxtsCaptureEnabled and
  OxtsCapture (NetworkAdapterGuid, IpAddress, NcomPort),
  OxtsConfiguration.NetworkAdapterGuid, Compression.MaxRetries,
  Compression.RetryDelaySeconds, Compression.FileLockTimeoutSeconds,
  NetworkAdapterDescription, CurrentVehicleUsage,
  SelectedVehicleNumber, SaveCalSnapshotEnabled,
  APICommErrorMsgDelayTime, and SkipSubscriptionOnCacheHit.
- Added True/False validation for additional boolean settings
  (MuteVoiceRecordingMessages, AudioToTextConversion,
  AlternateRecordEnabled, EnableAltRecReStartAfterRecordStop,
  OxtsCaptureEnabled, EnableTimeSync, TimeMachineConfiguration.Enabled,
  PtpAssumeLocked, SaveCalSnapshotEnabled, SkipSubscriptionOnCacheHit,
  the Compression file-type/DeleteAfterCompression flags, and
  ZipMF4Files) and range/format validation for additional numeric and
  enum settings (TimeMachineConfiguration.Port, OxtsCapture.PtcPort,
  HesaiConfig.HttpPort, TimeMachineConfiguration.PollMs,
  APICommErrorMsgDelayTime, Compression.MaxRetries/RetryDelaySeconds/
  FileLockTimeoutSeconds, and TimeSyncConfiguration.Provider).
- Replaced the native Hesai PTC/TCP-9347 interop path for capture
  manifest metadata with a managed HTTP client (HesaiHttpApi.vb)
  querying the device's pandar.cgi JSON API (device_info, lidar_config,
  lidar_data, lidar_sync, lidar_monitor, TimeStatistic,
  PTP_lock_offset, lidar_calibration). The PTC path was unreliable
  against live units, repeatedly failing with "invalid input
  parameter" / ret=-1 errors; HTTP is stateless and requires no native
  interop. Added HttpPort parsing to config.xml/GM_ResidentClient.vb so
  the HTTP path works independently of the native SDK.
- Upgraded the sidecar capture manifest (PcapEventBridge.CaptureManifest)
  to schema version 2, with device identity, live configuration/status
  snapshots, angle-correction and firetimes calibration blobs, and
  extrinsic mounting data populated from the new HTTP metadata source.
  Fields are nullable where the device does not report them, so
  missing data serializes as absent rather than a misleading default
  such as 0 or false.
- Added an on-demand "Generate Manifest" button to the Configuration
  Editor, allowing operators to produce and verify a device manifest
  (and confirm HTTP reachability) outside of an active capture
  session.
- Extended the Hesai HTTP-based capture manifest schema with decoded,
  human-readable companion fields alongside the existing raw codes:
  ReturnModeName, RotateDirectionName, PtpProfileName, and
  MotorTypeName. Documented LidarDataFormat as reported by the device
  but not used by downstream tooling.
- Fixed the Configuration Editor opening behind the always-on-top
  Login screen; the Login form now temporarily relinquishes topmost
  status and is sent to the back while the editor is displayed, then
  restored afterward.
- Moved sidecar capture manifest generation off the capture-stop path
  and onto a background task, removing a 20-30 second delay between
  recording sequences that was caused by blocking on Hesai HTTP
  metadata queries and PCAP checksum computation during capture stop.
  Manifest state (integrity counters, event markers, time-sync status)
  is snapshotted synchronously before the background write so it is
  not lost when the next sequence starts. Pending manifest writes are
  now awaited during device shutdown/dispose to avoid losing an
  in-flight manifest.

Version 7.5.2.0
----------------
- Fixed an issue where a malformed entry in config.xml (an invalid XML
  comment) could prevent the application's configuration from loading
  correctly.
- Replaced the old "Default Configuration" screen with the improved
  Configuration Editor throughout the application (login screen, main
  menu, and startup).
- Added a clear prompt to open the Configuration Editor if config.xml
  fails to load at startup, instead of showing a confusing legacy
  dialog.
- Minor documentation updates to the network setup guide (no functional
  changes to the application).
